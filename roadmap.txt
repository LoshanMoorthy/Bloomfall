Coordinate System
----------------
(0,0)

world+X increases -> down-right
world+Y increases -> down-left

AABB Collision
----------------
Axis-Aligned Bounding Box

Rectangles overlap if:

player.x < wall.x + wall.w
player.x + player.w > wall.x
player.y < wall.y + wall.h
player.y + player.h > wall.y

Current collision strat:
- move on X
- if collision -> revert X
- move on Y
- if collision -> revert Y

Isometric Rendering
----------------
Normal 2D is rendered:
screen_x = x * tile_width
screen_y = y * tile_height

Isometric:
screen_x = (x - y) * (tile_width / 2)
screen_y = (x + y) * (tile_height / 2)

The world is still just normal 2d coordinates/grid.
Only thing that changes is the rendering which renders the grid in a
"diamond" form giving the illusion of fake depth/perspective.

Potentially:
world[x][y]
or..
world[x][y][z]

Which then would allow:
- block placing
- mining
- stacked tiles
- caves/underground system

Cube Rendering (2D iso, flat-shaded)
----------------
This topic is an "installment" to the above.

A "cube" is just 3 flat-colered faces drawn tat the right screen
offsets. No texture, no 3D, no OpenGL. Basically, the 3D look is fake:
It comes from drawing a top diamond + 2 side faces in 3 brightnesses.

That means everything is built from ONE point:
T = top corner of the dia.

T is projected like a normal iso tile, but with a height term.

cx = origin_x + (x - y) * (tile_width / 2)  - camera.x
cy = origin_y + (x + y) * (tile_height / 2) - camera.y - z * cube_h

So the only new thing compared to a flat iso is - z * cube_h.
Higher z just pushes the cube UP on screen so just a smaller y.
world[x][y][z].

The 7 points (hw = tile_width/2, hh = tile_height/2):

Top diamond:
  T (cx,      cy)
  R (cx + hw, cy + hh)
  B (cx,      cy + 2*hh)
  L (cx - hw, cy + hh)

Bottom 3: drop B, R, L straight down by cube_h -> B', R', L'

Visible faces (only 3 - we never see back/bottom/far from the fixed iso cam):
  TOP   = T, R, B, L
  LEFT  = L, B, B', L'
  RIGHT = R, B, B', R'

Faces -> triangles: each 4-corner face is 2 triangles,
so top = (T,R,B) + (T,B,L)
One cub has 3 faces * 2 = 6 triangles which gives us 18 vertices.

Depth sorting
----------------
With height, a cube can sit in front of a taller cube behind it.
So we draw back-to-front or the back ones paints over the front.
Rule: smaller (x + y) = further back = draw first.
To do that we collect all drawables into a list, sort by (x+y, then z), draw.
PLayer is just another item in that list which sorts into the world
automatically (walk behind a tower = hidde, in front = covers it).
A manual version of the GPUs depth buffer.

Texture / UV mapping (the 2 squares model)
----------------
A texture is wrapped onto geometry by pairing each vertex to a
spot on the image. So we think 2 separate squares:

    pos space: center = 0, edges -0,5 .. +0.5
    UV space:  corner = 0, edges 0    .. 1

Same corner, different rules. bl = (-0.5,-0.5) in pos, (0,0) in UV.
Each vert = a string linking a pos-point to a UV-point.
GPU interpolates UVs across the triangle, fragment shader samples
the image at each pixels UV. (sampling = texture(uTex, vUV))

Vertex layout: each row = one corner. columns = attributes.
count per attribute.
    pos = 3 (x,y,z, 3D space)
    UV  = 2 (u,v,   2D img)
VAO receipe (glVertexAttribPointer) must match: 3 for pos, 2 for UV.

Normals + Directional Lighting
----------------
Lighting needs to know which way each surface face so the normal,
a vector perpendicular to the face. Each cube face's 6 verts share
one normal (top face -> (0,1,0) right face -> (1,0,0), etc).

Vertex layout gew: pos(3) + normal(3) + uv(2) = 8 floats/vertex.
VAO: attr0=pos(3) off0, attr1=normal(3) off3, attr2=uv(2) off6, stride 8.

The whole lighting model in one line (fragment shader):
    diff = max(dot(N, L), 0.0)
N = surface normal, L = direction to the light.
dot measures alignment: face pointing at light = 1 (bright),
perpendicular = 0 (dark). clamp at 0 so backfaces dont go negative.

final = ambient + diff * strength
ambient around 0.25 keeps shadowed faces from being pure black.
